> 기준 시점: 2026-07-30  
> 대상: `/` 공개 랜딩 페이지, `/privacy` 개인정보처리방침, 공개 문의·다운로드 기능  
> 목적: 이 문서만 읽은 다른 AI가 현재 사이트의 정보 구조, 화면 순서, 문구, 데이터 출처와 주요 동작을 바로 떠올릴 수 있도록 한다.

## 0. 한 문장으로 보는 사이트

아델슨의 MDI 압축성형 목재 팔레트를 소개하는 B2B 단일 페이지 사이트이며, **운영 문제 제기 → 제품·제조 설명 → 제조사 홍보영상 → 장점 → 시험 데이터 → 시연영상 → 원문 자료 → 제품 라인업 → 적용 검토 → 환경 데이터 → 회사 역량 → 제품 홍보영상 → 견적 문의** 순서로 신뢰를 쌓고 문의 접수로 연결한다.

## 1. 사이트의 기본 구조

### 기술 구조

- 프런트엔드: Next.js App Router + React + TypeScript + Tailwind CSS
- 공개 메인 페이지: `src/app/page.tsx`
- 전역 레이아웃 및 메타데이터: `src/app/layout.tsx`
- 정적 기본 콘텐츠: `src/lib/constants.ts`
- CMS 콘텐츠 결합: `src/lib/websiteContent.ts`
- CMS 데이터베이스: Supabase PostgreSQL + Prisma
- 이미지·영상·PDF: Supabase Storage의 공개 URL
- 문의 저장: PostgreSQL의 `Inquiry`, `Customer`, `Company` 등
- 첨부파일 저장: Supabase Storage의 문의 첨부 전용 버킷
- 공개 페이지 재검증 주기: 300초(5분)

### 콘텐츠 결합 원칙

사이트는 모든 문구를 CMS에서 읽는 완전한 CMS 방식이 아니다.

1. 제목, 설명, 수치, 카드 목록 등 대부분의 핵심 문구는 코드에 기본값으로 고정되어 있다.
2. 관리자 앱 CMS는 현재 사이트 기본정보와 이미지·영상·PDF, 문서 메타데이터 일부를 관리한다.
3. CMS 데이터가 있으면 해당 자산과 문서 정보가 기본값 위에 덮어써진다.
4. CMS 조회가 실패하면 코드 기본값으로 공개 페이지가 계속 렌더링된다.
5. 메인 페이지는 서버 컴포넌트이고, 검색·필터·모달·폼 같은 상호작용 영역만 클라이언트 컴포넌트다.

### 전체 화면 공통 규칙

- 본문 최대 너비: 대부분 `1200px`
- 데스크톱 좌우 여백: 대체로 `32px`
- 모바일 좌우 여백: 대체로 `20px`
- 일반 섹션 상단 여백: `48px`
- 일반 섹션 하단 여백: 모바일 약 `56px`, 데스크톱 약 `72px`
- 카드 모서리: 작은 둥근 사각형
- 주요 CTA 최소 높이: 모바일 `44px`, 데스크톱 `48px`
- 한글 제목은 단어 단위 줄바꿈을 우선하고, 긴 데이터는 강제 줄바꿈이 가능하다.
- 모바일 입력창은 iOS 자동 확대를 막기 위해 최소 `16px` 글자 크기를 사용한다.
- 모션 감소 설정이 켜져 있으면 스크롤·전환 애니메이션을 사실상 끈다.

## 3. 헤더와 내비게이션

헤더는 화면 상단에 고정되는 sticky 구조다. 페이지 내 섹션으로 이동하며 별도 페이지 전환은 하지 않는다.

### 데스크톱 헤더

- 높이: 약 `76px`
- 왼쪽: 아델슨 로고
- 가운데: 6개 대분류 메뉴
- 오른쪽: `견적 문의` CTA
- 메뉴에 마우스를 올리거나 키보드 포커스가 들어가면 전체 하위 메뉴가 가로 사이트맵 형태로 펼쳐진다.
- 현재 보고 있는 섹션의 대분류가 굵고 진한 녹색으로 활성화된다.
- 터치 기반 큰 화면에서는 첫 터치로 메뉴를 열고 다음 동작으로 이동하게 한다.
- Escape 키로 펼친 메뉴를 닫는다.

### 데스크톱 메뉴 구성

1. 제품 소개

### 모바일 헤더

- 상단 로고 행 + 하단 가로 스크롤 칩 내비게이션
- 로고 행 높이: 휴대폰 약 `48px`, 중간 화면 약 `56px`
- 아래로 충분히 스크롤하면 로고 행을 감춰 콘텐츠 공간을 확보하고, 위로 스크롤하면 다시 보인다.
- 내비게이션 칩은 손가락으로 가로 스크롤할 수 있다.
- 현재 섹션의 칩은 녹색 배경과 흰색 글자로 표시되고 자동으로 화면 가운데에 가까워진다.
- 모바일 칩 순서:
  1. 홈
  2. 도입 전 과제
  3. 제품 소개
  4. 성능·기술
  5. 제품 라인업
  6. 적용 분야
  7. 환경 데이터
  8. 회사·생산
  9. 견적 문의

### 섹션 이동 규칙

- 데스크톱은 부드러운 스크롤을 사용한다.
- 모바일은 고정 내비게이션의 높이를 계산하여 즉시 정확한 위치로 이동한다.
- 이동 후 섹션 시작 부분이 고정 내비게이션 바로 아래와 맞닿도록 오프셋을 적용한다.
- 새로고침이나 뒤로가기로 돌아왔을 때 세션에 저장된 스크롤 위치를 복원한다.

- 한국어 요약은 선택한 문서 카드만 아래로 확장된다.
- 영상·제품·PDF 모달이 열리면 본문 스크롤을 잠근다.
- 대부분의 모달은 바깥 클릭과 Escape로 닫을 수 있다.
- 이미지 확대 기능은 공통 컴포넌트에 존재하지만, 현재 주요 제품·문서 썸네일 대부분은 확대를 끄고 별도 상세 기능을 사용한다.

## 11. 다른 AI가 반드시 알아야 할 현재 구현상의 함정

### 두 홍보영상의 내부 필드명과 실제 의미가 반대처럼 보인다

- `productOverviewVideo` 필드에 들어 있는 공개 콘텐츠는 실제로 **회사·생산 및 기술 소개영상**이다.
- `companyOverviewVideo` 필드에 들어 있는 공개 콘텐츠는 실제로 **제품 구조 및 주요 특징 소개영상**이다.
- 화면 문구와 영상 내용은 현재 올바르게 맞춰져 있으므로, 내부 필드명만 보고 제목을 다시 바꾸면 안 된다.

### 섹션 순서는 현재 코드에서 사실상 고정된다

- 타입에는 CMS의 `sectionOrder`, `sectionVisibility`가 있으나 현재 `getWebsiteContent()`는 이 값을 실제 반환 데이터에 넣지 않는다.
- 따라서 현재 공개 페이지는 `page.tsx`의 기본 순서를 사용한다.
- `benefits`는 항상 `verification` 앞에 삽입된다.
- `documents`는 항상 `performanceVideos` 바로 뒤에 삽입된다.

### 별도 카탈로그 섹션은 사용하지 않는다

- `CatalogSection.tsx` 파일은 남아 있을 수 있지만 메인 페이지에서는 렌더링하지 않는다.
- 카탈로그는 문의 섹션 왼쪽의 `제품 카탈로그 다운로드` CTA로만 제공한다.

### 실제 문서 필터는 등록 문서에서 동적으로 만든다

- 코드에 더 많은 문서 카테고리 상수가 있어도, 현재 화면에는 실제 등록된 문서 유형만 표시한다.
- 현재는 전체 / 제품 성능 시험 / 포름알데히드 시험 / 탄소발자국 검증만 보인다.

### Hero 모바일 자산

- CMS에는 `heroDesktop`과 `heroMobile` 자산이 모두 존재한다.
- 현재 공개 콘텐츠 로더는 `heroDesktop`의 원본 URL을 모바일 이미지로 우선 사용한다.
- 별도 `heroMobile` 자산이 있다는 사실만 보고 현재 화면이 그것을 사용한다고 단정하면 안 된다.

### 접수 완료 문구와 접수번호

- 서버는 정상적인 `registrationNumber`와 내부 `inquiryId`를 모두 반환한다.
- 현재 클라이언트 성공 문구는 `result.inquiryId`를 `접수번호`라고 표시한다.
- 따라서 화면 성공 메시지에서 YYMMDDnnnn이 아닌 내부 ID가 보일 가능성이 있다. 이 부분은 현재 구현 상태를 기술한 것이며 향후 수정 후보다.

### 업로드 용량

- 관리자 CMS/스토리지의 큰 파일 설정과 공개 문의 첨부 제한은 별개다.
- 공개 문의 첨부는 현재도 **파일당 50MB**, 최대 3개다.
- 큰 파일 안내 이메일은 `bossjhb@naver.com`이다.
